# T08 — Can a simple baseline distinguish crown loss from image displacement?

## Brief

Run an end-to-end development baseline on the four [reserved windows](../T05-paired-coverage/development-windows.geojson) at `2ac905e`. Start with the [T01](../T01-imagery/t01-windows.json) and [T05](../T05-paired-coverage/window-evidence.json) manifests and their verified replay commands. Use only the eight recorded rasters and their existing spatial support. Reserve this folder and ignored cache `data/imagery/t08/`.

1. Verify pixels, dates, transforms and masks. Pin one common grid and resampling rule. Record valid and unknown area by site. Reuse the [stable-feature diagnostics](../T05-paired-coverage/alignment.json). Distinguish evidence for a correction from spatially separate controls used to check it. Report residuals in metres, rejected controls and places with inadequate evidence, including seam crossings.
2. Run a reproducible, inexpensive rule for crown cover at each date, for example a vegetation index with a local texture cue to distinguish grass. Difference the two masks for gross loss and form connected events before filtering by area. Preserve thresholds, connectivity, subthreshold components, edge truncation, event IDs, geometry, dates and uncertainty reasons. Start with 0.10 acre and show the effect of 0.05 and 0.25 acre. Document failures on grass, shadow and crown edges.
3. Compare the same detector on the common grid before and after any supported correction. Perturb alignment over the range supported by local controls and report how many candidates and how much area persist. Where no correction can be checked, retain that site as registration-uncertain. Inspect paired chips from flagged areas **and** apparently unchanged areas at each site using a recorded selection rule. Include misses, false alarms and ambiguous examples when observed. These are development judgments.
4. Deliver a pinned command, configuration, compact event layer and site table. Reconcile scored, unknown and excluded areas to the input windows. Replay from verified inputs and compare event IDs, geometry, areas and counts within declared tolerances. Report runtime and storage. Keep imagery out of Git.

Recommend either a controlled challenger on the same inputs, a targeted development read to resolve a named failure, or stopping at the scale the imagery can support. Explain which site and event size motivate the choice. A reproducible empty queue or inconclusive result is a valid outcome. This run selects the next experiment. Accuracy, citywide coverage and operational yield require independent evidence.
